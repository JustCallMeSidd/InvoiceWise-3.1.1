### Full lifecycle
- **CREATE**:
  - **Trigger**: `POST /api/raw-materials`.
  - **Files written in same operation**:
    1. `raw_materials.json` (`server.js:3008`)
    2. `raw_material_batches.json` (`server.js:3052`, if initial stock > 0, creates baseline opening batch)
    3. `raw_material_transactions.json` (`server.js:3093`, if initial stock > 0, creates `PURCHASE_RECEIPT` transaction)
    4. `manufacturing_audit.json` (`server.js:3205`, logs `INVENTORY_IN` audit event)
  - **Failure behavior**: Non-atomic multi-file write without rollback. If writing `raw_material_batches.json` fails, `raw_materials.json` retains the record with initial stock but child batch is missing, causing `reconcileRawMaterialBatches()` to attempt self-healing on next launch.
- **UPDATE**:
  - `PUT /api/raw-materials/:id`: Mutates metadata (`name`, `unit`, `minStock`, `cost_per_unit`, `supplier`, `hsn`, `notes`). Cascades `unit` and `name` changes to all associated child batches in `raw_material_batches.json` (`server.js:3155`).
  - Stock mutations occur via:
    - `POST /api/raw-materials/:id/add-stock`: Increases `current_stock`.
    - `POST /api/products/:id/fill-bottles`: Decreases `current_stock` by `packagingNeeded`.
    - `POST /api/manufacturing-batches/commit`: Decreases `current_stock` by consumed ingredient amount.
    - `DELETE /api/products/:id/variants/:variantId` (`REVERSE`): Increases `current_stock` by restored packaging.
    - `POST /api/raw-materials/:id/delete-vendor`: Decreases `current_stock` by purged vendor stock.
- **DELETE**:
  - **Mechanism**: Hard delete via `d.raw_materials.splice(idx, 1)` (`server.js:3286`).
  - **Pre-condition Checks**: Blocked with HTTP 400 if referenced in:
    1. Active manufacturing batches (`server.js:3170`)
    2. Recipe ingredients in `recipes.json` (`server.js:3172`)
    3. Product variants as `packagingRawMaterialId` in `products.json` (`server.js:3189`)
  - **Cascading Effects**:
    - `raw_material_batches.json`: Slices out all child batches matching `rawMaterialId` (`server.js:3293`).
    - `manufacturing_audit.json`: Logs `DATA_DELETION` audit entry with correlation ID (`server.js:3278`).
    - `raw_material_transactions.json`: **NO CASCADING CLEANUP**. Historical transactions retain the deleted `rawMaterialId`, leaving orphan foreign keys.
  - **Reversal/Undo**: None. Hard delete is permanent.
- **Audit Logging**:
  - Creation with stock logs `INVENTORY_IN` to `manufacturing_audit.json` with correlation ID `AUD-YYYY-NNNNNN` (`server.js:3205`).
  - Updates log `INVENTORY_ADJUSTMENT` to `manufacturing_audit.json` (`server.js:3242`).
  - Deletion logs `DATA_DELETION` (`entityType: 'RAW_MATERIAL'`) to `manufacturing_audit.json` (`server.js:3278`).

- **Bottling Run**: `products.json` (`server.js:1456`) $\rightarrow$ `raw_materials.json` (`server.js:1468`) $\rightarrow$ `raw_material_batches.json` (`server.js:1469`) $\rightarrow$ `raw_material_transactions.json` (`server.js:1506`) $\rightarrow$ `manufacturing_audit.json` (`server.js:1533`) $\rightarrow$ `finished_goods.json` (`server.js:1559`) $\rightarrow$ `finished_goods_transactions.json` (`server.js:1560`).

### Known edge cases / validation gaps
- **Contradiction with Documentation**: Documentation claims all JSON writes are atomic. In reality, `POST /api/raw-materials` (`server.js:3008`), `PUT /api/raw-materials/:id` (`server.js:3138`), and `POST /api/import-data` (`server.js:2499`) call `writeJSON` which performs synchronous non-atomic `fs.writeFileSync`.
- **Concurrency Gap**: `POST /api/raw-materials/:id/add-stock` is not wrapped in `withInventoryLock`. Rapid concurrent inward calls can experience lost updates during read-modify-write cycles.
- **Orphan Transactions**: Deleting a raw material deletes the master and child batches but leaves historical records in `raw_material_transactions.json` pointing to a non-existent `rawMaterialId`.
- **Negative Stock Vulnerability**: `rm.current_stock` can theoretically be driven negative if external edits corrupt `raw_material_batches.json`, though runtime math enforces `Math.max(0, ...)` on bottling and batch commit.

    ```javascript
      const year = new Date().getFullYear();
      const prefix = `RMB-${year}-`;
      const rmbData = readJSON(RAW_MATERIAL_BATCHES_FILE) || { raw_material_batches: [] };
      let maxSeq = 0;
      (rmbData.raw_material_batches || []).forEach(b => {
        const id = b.id || b.batchId;
        if (typeof id === 'string' && id.startsWith(prefix)) {
          const num = parseInt(id.replace(prefix, ''), 10);
          if (!isNaN(num) && num > maxSeq) maxSeq = num;
    ```

### Cross-file transactions

### Known edge cases / validation gaps
- **No Transaction Rollback**: If a manufacturing commit exhausts stock on ingredient 3 of 5, earlier ingredients may have already been partially allocated in memory; the commit fails with 400 before writing, which protects disk, but if a crash occurs *during* the 8 sequential file writes, data drift occurs.
- **Stale Batch Reversal Block**: In variant deletion reversal (`server.js:1031`), if any original batch was deleted or purged, the entire reversal fails with HTTP 400 (`Original Raw Material batch ... no longer exists`), blocking automatic unwinding.

### Schema

    ```javascript
    // server.js:217-241
    function generateAuditCorrelationId() {
      const year = new Date().getFullYear();
      const prefix = `AUD-${year}-`;
      const mfgAudit = readJSON(MANUFACTURING_AUDIT_FILE) || { manufacturing_audit: [] };
      const rmTxns = readJSON(RAW_MAT_TXN_FILE) || { raw_material_transactions: [] };
      let maxSeq = 0;
      const checkId = (id) => {
        if (typeof id === 'string' && id.startsWith(prefix)) {

          if (!isNaN(numPart) && numPart > maxSeq) maxSeq = numPart;
        }

      (mfgAudit.manufacturing_audit || []).forEach(r => {
        checkId(r.auditCorrelationId);
        checkId(r.auditId);
      });
      (rmTxns.raw_material_transactions || []).forEach(r => {
    ```
